# Приватный Telegram-бот

Бот принимает текст, фото еды и голосовые сообщения. Перед записью он всегда
показывает структурированный черновик. Фото и аудиофайл не сохраняются в Git;
в `db/events/YYYY-MM-DD.jsonl` попадает только подтверждённое событие, исходный
текст и результаты анализа.

## Возможности

- текст, одиночные фотографии, альбомы до трёх фото и голосовые;
- анализ фото с диапазоном порции и уровнем уверенности;
- не более одного существенного уточняющего вопроса;
- кнопки `Сохранить`, `Исправить` и `Отмена`;
- идемпотентный импорт событий в SQLite;
- автоматическое обновление `dashboard/data.js`;
- `/today` — текущая сводка;
- `/finish 4` — завершение дня с пользовательской оценкой 4/5;
- `/sync` — один коммит и push за текущий день;
- необязательная автоматическая синхронизация после `/finish`.

## 1. Создание бота

1. Откройте официальный аккаунт `@BotFather` в Telegram.
2. Выполните `/newbot` и сохраните выданный токен.
3. Скопируйте конфигурацию:

   ```bash
   cp .env.example .env
   ```

4. Добавьте в `.env` значения `TELEGRAM_BOT_TOKEN` и `OPENAI_API_KEY`.

Не отправляйте токены в чат и не коммитьте `.env`. Если токен случайно попал в
логи или переписку, отзовите его через `@BotFather` и создайте новый.

## 2. Первый запуск и приватный доступ

Первый раз `ALLOWED_TELEGRAM_USER_IDS` можно оставить пустым. В таком режиме
бот отвечает только на `/whoami` и не обрабатывает данные здоровья.

```bash
./scripts/run_telegram_bot.sh
```

Отправьте боту `/whoami`, скопируйте числовой ID в `.env`:

```text
ALLOWED_TELEGRAM_USER_IDS=123456789
```

Перезапустите процесс. Бот принимает записи только от перечисленных ID и только
в личном чате.

## 3. Использование

Простой текст:

```text
сон 00:40–07:10, качество 3/5, энергия утром 2/5
```

Подпись к фотографии:

```text
обед 13:20; тарелка 26 см; съел всё; салат без масла
```

Можно отправить Telegram-альбом из вида сверху, сбоку и этикетки. Если части
альбома придут в разных сетевых пакетах, бот попросит сначала завершить уже
созданный черновик; в таком случае достаточно повторить альбом одним сообщением.

Завершение дня:

```text
/finish 4
```

До нажатия `Сохранить` данные существуют только как локальный черновик в
`data/bot/`. После подтверждения событие добавляется в `db/events/`, проецируется
в SQLite и обновляет страницу аналитики.

## 4. Один коммит в день

Для ручного пакетного коммита используйте `/sync`. Бот добавляет в staging
только файл событий выбранного дня и `dashboard/data.js`. Если там уже есть
посторонние staged-файлы, операция останавливается.

Чтобы синхронизация запускалась автоматически после завершения дня:

```text
AUTO_GIT_SYNC=true
```

На машине должны заранее работать `git commit` и `git push origin main` без
интерактивного запроса пароля; также задайте `user.name` и `user.email` для
этого клона. Если push не удался после успешного локального коммита, повторный
`/sync` отправит уже созданный коммит. События в любом случае остаются на диске.

## 5. Постоянная работа

Для работы 24/7 нужен постоянно включённый компьютер или небольшой приватный
сервер. Пример unit-файла находится в
`deploy/health-diary-bot.service.example`. Перед запуском сервиса:

- клонируйте приватный репозиторий в `/opt/health_diary`;
- создайте отдельного системного пользователя `healthdiary`;
- положите `.env` с правами только для этого пользователя;
- настройте Git-ключ с доступом только к этому репозиторию;
- убедитесь, что установлены Python 3.9+, SQLite CLI и Git.

## Приватность и стоимость

Текст, фото и голос передаются Telegram и OpenAI для обработки. Код бота не
сохраняет скачанные фото и аудиофайлы на диск. Вызовы OpenAI API оплачиваются
отдельно от подписки ChatGPT. Модель можно изменить через `OPENAI_MODEL`; модель
по умолчанию выбрана в пользу точности анализа фотографий.

Сырые события содержат чувствительные данные. Репозиторий и сервер должны
оставаться приватными, с резервной копией и ограниченным доступом.
