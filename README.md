# Health Diary

Минимальная база календаря здоровья на SQLite. Она хранит:

- питание с калориями и БЖУ;
- состав каждого приёма пищи и оценку клетчатки, витаминов и минералов;
- дневные основы питания: мясо, курица и рыба;
- тренировки;
- шахматные партии и победы;
- сон;
- оценку дня по пятибалльной шкале;
- дневные заметки и сводные показатели.

Проект также содержит автономный интерактивный дашборд и правила
бережной оценки еды по фотографиям.

## Быстрый старт

Создать локальную базу с начальными данными:

```bash
./scripts/init_db.sh
```

База появится в `data/health_diary.sqlite3`. Она атомарно пересобирается из
`db/schema.sql`, `db/seed.sql` и `db/nutrition_components.sql`, считается
локальным рабочим файлом и не коммитится. Последний файл хранит восстановленный
состав блюд, веса компонентов, уверенность оценки и ссылки на справочные
профили продуктов.

Посмотреть календарную сводку:

```bash
sqlite3 -header -column data/health_diary.sqlite3 \
  "SELECT * FROM daily_health_summary ORDER BY diary_date DESC;"
```

Явно обновить аналитический снимок и собрать production-дашборд:

```bash
./scripts/build_dashboard.sh
```

Затем открыть `dashboard/index.html` в браузере. Страница работает без сервера
и runtime-сети: React, ECharts и стили встроены в один HTML-файл. Dashboard v2
содержит связанные графики питания, сна, нагрузки и оценки дня, фильтры
периода, единый drawer даты, микронутриентную heatmap и отдельный экран
качества данных. Пропуск не превращается в ноль, а у средних показан знаменатель
`n/N`. Текущий день со статусом `in_progress` по умолчанию не попадает в
средние полного дня.

Данные и интерфейс собираются раздельно. Если snapshot уже актуален и нужно
поменять только код страницы, используйте:

```bash
./scripts/build_dashboard_ui.sh
```

Для разработки нужны Node.js и pnpm (`pnpm install`, затем
`pnpm run dashboard:dev`). Обычные записи дневника не обновляют snapshot;
полный `build_dashboard.sh` запускайте только когда явно нужен новый срез.

Микронутриенты рассчитываются по оценённым составляющим блюд и справочным
данным USDA FoodData Central. Эти значения описывают примерное поступление с
едой и не являются диагнозом дефицита; неизвестные соусы, соль и части рецептов
сохраняются как пробелы, а не как нулевое потребление.

## Как вносить данные

Короткие шаблоны для сна, еды, бега, зала и завершения дня находятся в
[`docs/quick-entry.md`](docs/quick-entry.md). Подробный аудит текущих данных,
варианты мобильного ввода и рекомендуемая архитектура Telegram-бота описаны в
[`docs/audit-and-roadmap.md`](docs/audit-and-roadmap.md). Воспроизводимая
методика оценки порций, БЖУ, витаминов и минералов зафиксирована в
[`docs/nutrition-estimation-protocol.md`](docs/nutrition-estimation-protocol.md),
а современный дизайн и аналитический контракт дашборда v2 — в
[`docs/dashboard-v2-spec.md`](docs/dashboard-v2-spec.md).

## Текущие данные

История продолжена до 25 августа 2026 года. В воспроизводимой базе находятся 18
завершённых календарных дней; 14–17 августа не записаны и не должны
трактоваться как нулевые дни. Дневные показатели находятся в
`daily_health_summary` и `daily_nutrient_summary`, месячные — в
`monthly_health_summary`, а визуальный срез — на странице аналитики. В рамках
работ 26 августа шесть подтверждённых семантических дублей компонентов 24–25
августа были устранены и закрыты регрессионной проверкой. Отдельное расхождение
общего веса записи 12 августа не исправлено без подтверждения исходных фактов
и явно показывается в блоке качества данных.
